# Ragic 建表清單

三件事：新開一張拜訪記錄表、客戶主檔補經緯度、（選用）新開一張工牌打卡表。

---

## 一、車輛拜訪記錄表

程式在「車子開走、拜訪結案」時寫一筆。停留期間不寫，所以不會有半成品記錄。

| 欄位名稱 | Ragic 型別 | 必填 | 範例 | 說明 |
|---|---|---|---|---|
| 日期 | 日期 `YYYY/MM/DD` | ✅ | `2026/09/28` | 以「到達時間」那天為準 |
| 車牌 | 文字 | ✅ | `ABC-1234` | 來自 Traccar 的裝置名稱 |
| 設備IMEI | 文字 | | `868120214425578` | 對不上車牌時用來追 |
| 駕駛 | 文字 | | `王小明` | 由 `GPS_DRIVER_MAP` 帶入 |
| 客戶 | 文字 | | `台中客戶甲` | 比對不到就留空，不會亂猜 |
| 客戶代號 | 文字 | | `C001` | 客戶主檔的代號或 Ragic 記錄 ID |
| 到達時間 | 文字 | ✅ | `2026/09/28 09:12:03` | 見下面「為什麼用文字」 |
| 離開時間 | 文字 | | `2026/09/28 10:48:31` | |
| 停留分鐘 | 數字 | | `96` | 整數，不帶單位 |
| 距客戶公尺 | 數字 | | `15` | 判斷比對品質用，大於 150 就要留意 |
| 緯度 | 文字 | | `24.1478` | |
| 經度 | 文字 | | `120.6737` | |
| 地圖連結 | 文字 | | `https://www.google.com/maps?q=...` | 自動生成，點了直接開地圖 |
| AI摘要 | 多行文字 | | `業務車上午到台中客戶甲停留約一個半小時，研判為現場拜訪` | |
| 性質 | 文字 | | `拜訪` | 見下面的固定選項 |
| 來源 | 文字 | | `moved_away` | 見下面的三種值 |

**「性質」的七個值**（AI 只會從這裡面選）

`拜訪`　`送貨`　`施工`　`取件`　`用餐休息`　`返回公司`　`不明`

建成「選單」型別也可以，但要把七個值都填進去，少一個那筆就寫不進來。
不確定的話先用「文字」，跑一陣子看實際分布再改成選單。

**「來源」的三個值**

| 值 | 意思 | 可信度 |
|---|---|---|
| `moved_away` | 正常結案。看到車子開走才結束 | 高 |
| `inferred_sparse` | 推估。停留期間只收到一個定位包，離開時間是估的 | 時間略為高估 |
| `offline_timeout` | 裝置離線逾時結案。離開時間是最後一次回報的時間 | 離開時間偏早 |

建議在 Ragic 做一個「來源不等於 moved_away」的篩選檢視，
定期看一下有多少筆是估的。比例太高代表回報間隔設太長，
把定位器的 `TIMER` 第二個參數調小就會改善。

**為什麼到達/離開時間用「文字」不用「日期」**

程式送的是 `2026/09/28 09:12:03`。Ragic 的日期欄位對格式很挑，
格式設定沒對上會靜默寫不進去，而且很難察覺。
先用文字保證寫得進去，跑穩之後想排序再改成日期欄位。
真的要改，Ragic 的日期格式要設成 `YYYY/MM/DD HH:mm:ss`。

## 二、客戶主檔要補兩個欄位

表：`ragicsales-order-management/20004`

| 欄位名稱 | 型別 | 說明 |
|---|---|---|
| 緯度 | 文字或數字 | 例 `24.1477` |
| 經度 | 文字或數字 | 例 `120.6736` |

**沒有座標的客戶會被程式略過**，不影響其他客戶，但那家的到點就永遠比對不到。

補座標的做法：把客戶地址匯出成一欄，用 Google Geocoding API 跑一次轉成座標再貼回去。
客戶不多的話，直接在 Google 地圖上右鍵點座標複製也行。

**有些地址轉出來會偏掉**，特別是工業區、新重劃區、只寫到路名沒有門牌的。
建議轉完之後快速掃一遍，把明顯離譜的（例如落在海上或別的縣市）手動修掉。

## 三、工牌打卡表（選用）

只有買「工牌型」設備才用得到。沒設定 `RAGIC_PUNCH_SHEET` 的話程式會自動跳過，
不會報錯。

| 欄位名稱 | 型別 | 必填 | 範例 |
|---|---|---|---|
| 日期 | 日期 | ✅ | `2026/09/28` |
| 工牌名稱 | 文字 | ✅ | `王小明工牌` |
| 設備IMEI | 文字 | | `868120214425578` |
| 類型 | 文字 | | `上班` 或 `下班` |
| 時間 | 文字 | ✅ | `2026/09/28 08:02:11` |
| 緯度 | 文字 | | `24.1477` |
| 經度 | 文字 | | `120.6736` |
| 地點 | 文字 | | `台中客戶甲` |
| 里程公尺 | 數字 | | `0` |

## 四、建表步驟（走匯入最快）

手動一個一個加十六個欄位很花時間，而且型別容易設錯。用匯入的：

1. Ragic 後台選「**從 Excel 建立表單**」，上傳 `ragic/車輛拜訪記錄-匯入用.csv`
2. Ragic 會依欄位名稱自動建好表，並匯入兩筆資料：
   - 一筆 `PROBE...` 開頭的探測記錄（下一步要用）
   - 一筆看得懂的範例記錄
3. 確認型別：**停留分鐘**和**距客戶公尺**要是「數字」，其餘維持文字
4. 記下網址列的表單路徑，像 `ragicproject-management/21`
5. 到「表單權限」把服務帳戶 `Claude YSPE` 加進去，給讀寫權限

工牌打卡表同理，用 `ragic/工牌打卡-匯入用.csv`。

## 五、抓欄位 ID（一定要做）

**Ragic 的 POST 只認欄位 ID，不認中文欄位名。** 送中文名會回 SUCCESS 但欄位是空的，
這是最容易卡住又最難查的坑。

### 做法 A：在本機跑工具（建議）

金鑰只存在你自己的環境變數裡，不會出現在網址列、瀏覽器歷史、也不會印出來。
工具只印欄位編號。

```bash
cd gps
npm install
RAGIC_API_KEY=你的key node tools/probe-fields.js check-in-system/15 visit
```

輸出就是可以直接貼進環境變數的那一行：

```
RAGIC_VISIT_FIELDS={"date":"1002801","plateNum":"1002802", ...}
```

其他兩張表：

```bash
RAGIC_API_KEY=xxx node tools/probe-fields.js <打卡表路徑> punch
RAGIC_API_KEY=xxx node tools/probe-fields.js ragicsales-order-management/20004 customer
```

### 做法 B：瀏覽器直接看（不得已才用）

> ⚠ **這個做法會把 API Key 留在瀏覽器歷史紀錄裡**，而且如果瀏覽器有同步，
> 會跟著上傳到雲端。能用做法 A 就不要用這個。真的用了，事後去清除該筆歷史紀錄，
> 並考慮到 Ragic 後台重新產生一把 API Key。

網址格式：

```
https://ap10.ragic.com/Fan28/<表單路徑>?api&naming=fid&APIKey=<你的KEY>
```

回傳的 JSON 裡，左邊數字是欄位 ID，右邊是探測標記，照下表對照：

| 看到的值 | 對應的設定名稱 |
|---|---|
| `2001/01/02` | `date` |
| `PROBEPLATE` | `plateNum` |
| `PROBEIMEI` | `imei` |
| `PROBEDRIVER` | `driver` |
| `PROBECUSTOMER` | `customer` |
| `PROBECUSTCODE` | `customerCode` |
| `2001/01/02 03:04:05` | `arrivedAt` |
| `2001/01/02 06:07:08` | `departedAt` |
| `91001` | `durationMinutes` |
| `91002` | `distanceMeters` |
| `PROBELAT` | `lat` |
| `PROBELNG` | `lng` |
| `PROBEMAPURL` | `mapUrl` |
| `PROBESUMMARY` | `summary` |
| `PROBECATEGORY` | `category` |
| `PROBESOURCE` | `source` |

**JSON 內容本身沒有機密**（只有欄位編號和 PROBE 標記），但**網址有**。
要拿給別人看就只貼 JSON，絕對不要貼網址。

## 六、驗證寫得進去

環境變數都設好之後，用模擬器送一趟完整拜訪，看 Ragic 有沒有長出記錄：

```bash
AZLIOT_TF_KEY=xxx node tools/simulate.js https://你的網址/azliot/lpush
```

**Ragic 沒長出東西的話按這個順序查**

1. 服務的 log 有沒有寫「寫入拜訪」？沒有代表問題在前面，不是 Ragic
2. 有寫入但 Ragic 沒資料 → 欄位 ID 錯了，重跑一次 probe
3. 記錄有了但欄位空白 → 那個欄位的 ID 對到別的地方，或型別不符
4. 停留分鐘是空的 → 欄位型別不是「數字」，或 Ragic 那格設了單位
5. 完全沒反應 → 服務帳戶 `Claude YSPE` 沒有這張表的權限
