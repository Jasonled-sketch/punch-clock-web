# 宮廟雲：系統架構

一套程式，四個方案。方案只決定「開哪些功能、資料放哪裡」，櫃台操作畫面一致，升級不用重新教學。

## 1. 宮廟類型 × 組織型態 × 章程

| 類型 | 常見對象 | 可選組織型態（預設在前） | 產出文件 |
| --- | --- | --- | --- |
| 祠 | 宗祠、家廟 | 派下員大會制（祭祀公業）、管理人制 | 規約／章程 |
| 堂 | 齋堂、鸞堂、佛堂 | 管理委員會制、管理人制、一貫道管理委員會制 | 組織章程 |
| 壇 | 神壇、私人壇 | 管理人制、管理委員會制 | 組織章程 |
| 宮 | 道教、民間信仰 | 管理委員會制、管理人制、信徒大會制 | 組織章程 |
| 寺 | 佛教寺院 | 執事會制（住持）、信徒大會制 | 組織章程 |
| 殿 | 道教、民間信仰 | 管理委員會制、管理人制、信徒大會制 | 組織章程 |

- **有委員會**：管理委員會制、信徒大會制、執事會制、派下員大會制。
- **沒有委員會**：管理人制，由管理人一人負責，重大事項開信徒會議。
- 章程骨架依內政部五種「非財團法人制寺廟組織或管理章程範例」，涵蓋寺廟登記應記載的 12 個事項。祠堂屬祭祀公業者，依祭祀公業條例改稱「規約」。
- 每份章程同時附一份 **〈香油及點燈收入管理辦法〉**，內容就是本系統的作業流程：當場開收據、不得跳號、作廢留號、每日兩人點收、月報、公開姓名遮一字、備份。**廟方採用章程，等於採用我們的系統流程。**
- 程式：`charter.js`（`TEMPLE_TYPES`、`ORG_TYPES`、`buildCharter()`、`buildRules()`）。

> 範本僅供參考，送件前需經所在地民政單位確認。

## 3. 芳名錄海報・帆布

- 名單來源：油香／點燈（依年度、項目），以及每場法會、慶典、建醮。只列出同意公開姓名者，依金額由高到低。
- 版面：直式（由右至左，傳統芳名錄）或橫式；紅底金字或白底紅字；金額轉國字大寫。
- 尺寸：A4、A3、對開、帆布 60×90／90×180／120×240 cm；字級依人數自動縮放填滿。
- 輸出：**SVG 向量檔**（交輸出中心，任意放大不失真）、PNG（72～300 dpi）、直接列印。
- 字型：優先使用標楷體（Windows 內建），沒有時改用系統明體。送輸出中心前建議轉 PNG，或請對方安裝同一套字型。
- 程式：`poster.js`（`posterSVG()`、`cnAmount()`、`svgToPng()`）。

## 3-1. 陣頭廠商專區（豪華以上）

豪華版的核心賣點：入門、標準版的廟沒有這份行情，請陣頭只能靠人脈。

- 內容：陣頭名稱、類別、地區、人數、各宮廟評價（星等與筆數）、**出陣價格區間**、**譽昇認證**（立案、保險、無不良紀錄，由我們審核）。
- 宮廟可以把陣頭加入「我的陣頭」，出陣後評價；評價經平台審核後列入。
- 資料由雲端平台集中維護（`vendors.js` 目前是虛構範例資料）。

**防外流設計**

| 層 | 做法 | 對付什麼 |
| --- | --- | --- |
| 明顯浮水印 | 整區斜向重複「宮廟名稱＋用戶編號＋時間＋操作人員」 | 截圖、手機翻拍：一看就知道是哪間廟 |
| 隱形浮水印 | 每張卡片底層極淡的 `#用戶編號`，調高對比才看得到 | 有人把明顯浮水印修掉 |
| 浮水印自動補回 | 有人用開發者工具刪掉或隱藏浮水印，立即補回並記錄 | 技術型移除 |
| 禁止選取、禁止列印 | 專區文字不能選取；列印時整區隱藏 | 直接複製、印出來 |
| 複製追蹤 | 若繞過限制複製，文字會附上來源說明與**零寬字元隱藏編號**；平台可貼上外流文字查出是哪間廟 | 文字外流到 LINE 群組 |
| 截圖鍵與切換視窗 | 按 PrintScreen 或切到截圖工具時，評價與價格區間模糊 3 秒，並記錄 | 電腦截圖 |
| 查看紀錄 | 每次查看、截圖鍵、複製、浮水印被移除都記錄人員與時間，同步回平台 | 查出是誰 |
| 外流處理 | 平台可把該廟權限改為「鎖定價格區間」或「停用專區」 | 違規懲罰 |

> 限制：用另一支手機翻拍螢幕擋不住，只能靠浮水印追查來源，所以合約要寫明「專區資料禁止轉傳，違者停權」。

## 4. 入門（單機）的備份機制：有網路、沒網路都能用

入門方案的主要客戶是**沒有網路的廟**，所以備份不能依賴雲端；有網路的廟再多加一層。

| 層 | 沒有網路 | 有網路 |
| --- | --- | --- |
| 1. 本機資料 | 本機小伺服器＋單一資料庫檔，寫入即存檔（日誌模式，斷電不壞檔），開機自動檢查完整性 | 同左 |
| 2. 本機快照 | 每次關帳、每 50 筆自動快照，保留 30 天每日＋12 個月每月版本，誤刪、中毒都能回到前一版 | 同左 |
| 3. 隨身碟 A（常插） | 關帳時自動寫入加密備份檔 | 同左 |
| 4. 隨身碟 B（輪替） | 每週和 A 交換，由主委或總幹事帶離廟，防火災、失竊、勒索病毒 | 同左 |
| 5. 雲端加密備份 | — | 每天自動上傳加密檔；我們只存密文，打不開（年費 1,200，升級標準時直接轉成雲端資料） |
| 6. 紙本 | 每日印收入日報；另備預編號手寫收據（H 開頭）緊急使用，事後補登 | 同左 |

- 畫面常駐「備份燈號」：綠燈＝24 小時內備份成功；紅燈＝隨身碟沒插或備份失敗。
- 換機：備用主機插上隨身碟，輸入備份密碼，約 30 分鐘恢復。
- 耐用：無風扇主機、SSD、UPS（停電時自動關帳並安全關機）。
- **已實作**（`local-server/`）：Node.js 本機伺服器＋SQLite 單一資料庫檔（WAL、完整寫入）、自動加密備份到本機快照與所有本廟備份碟、保留規則、換機還原、手寫收據補登。安裝與維修步驟見 `local-server/INSTALL.md`。

## 5. 資訊安全架構

| 層 | 做法 |
| --- | --- |
| 裝置 | Windows 11 專業版 BitLocker 全碟加密；BIOS 密碼、禁止 USB 開機；一般使用者帳號＋指派存取（只能開本系統）；閒置自動鎖定 |
| 帳號 | 每位人員 PIN 登入；角色分權：櫃台、會計、主委、管理員；作廢、修改金額需主管 PIN |
| 稽核 | 每筆新增、作廢、修改寫入**不可竄改的操作紀錄**（雜湊鏈），委員會可隨時查核，也是防弊賣點（入門版已實作；關帳核對碼抄在紙本日報，防止整條鏈被重算） |
| 資料 | 本機檔案加密；備份檔 AES-256-GCM，金鑰由廟方密碼經 PBKDF2 衍生；我們預設不持有密碼，救援金鑰寫入合約才保管 |
| 雲端 | 全程 HTTPS；每間廟資料隔離；管理後台雙重驗證；每日備份與還原演練；主機放在台灣區域 |
| LINE | 驗證 LINE 簽章；只存 LINE 使用者 ID 與綁定手機；推播內容不放完整個資 |
| 個資 | 公開姓名需信眾同意、顯示遮一字；只收必要欄位；信眾可要求查詢、刪除；外洩時依個資法通知 |
| 維運 | 我們的人員要遠端連線，需廟方當次授權並留紀錄；每季資安檢查 |

## 6. 部署架構

```mermaid
flowchart LR
  subgraph 廟內
    PC[櫃台主機<br>PWA＋收據印表機]
    LED[字幕機<br>HDPlayer／HD2020／C-Power]
    TV[電視牆<br>Android 電視盒]
  end
  subgraph 雲端（標準以上）
    API[API＋資料庫]
    GW[字幕機閘道]
    SMS[簡訊閘道]
    JOB[排程：自動提醒・月報（豪華以上）]
    SYNC[LINE・FB・官網同步（旗艦）]
  end
  PC -- 入門：只存本機 --> PC
  PC -- 標準以上 --> API
  API --> GW --> LED
  API --> TV
  API --> SMS
  JOB --> SMS
  API --> SYNC
```

- **入門**：主機裝好 PWA，資料存在本機，每週備份到隨身碟（寫在管理辦法裡）。
- **標準以上**：同一套前端，把 `store` 換成雲端 API，資料每日自動備份。
- **字幕機**：灰度全彩卡可設定成主動連回雲端閘道，廟裡不必放電腦；單雙色卡或舊卡則在廟裡放樹莓派中繼。電視牆直接開網頁。

## 7. 資料模型（原型）

- `temple`：名稱、類型、組織型態、主神、地址、負責人、章程參數
- `records`：收據編號（民國年月日-流水號）、日期、信眾、手機、地址、項目、數量、金額、是否公開、作廢
- `led`：播報佇列
- `sms`：推播紀錄
- `rules`：全自動開關
- `events`：法會、慶典、建醮（`kind`；項目或職稱、姓名、金額）
- `troupes`：陣頭

## 8. 下一步

1. 後端：選定雲端資料庫與 API，把 `load()`、`save()` 換成 API 呼叫，並加上帳號權限。
2. 字幕機閘道：先做灰度全彩卡的 `UpdateProgram`，需要實體控制卡測試。
3. 收據格式：依廟方現用的收據尺寸（三聯單、A5、熱感紙）調整列印版面。
4. 章程：由民政或法律專業人士審閱範本後，再作為正式產品內容。
5. 簡訊閘道、LINE 官方帳號串接。
