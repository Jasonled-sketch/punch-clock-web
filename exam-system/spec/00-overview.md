# 系統總覽

## 資料流

```
小朋友手機
   │ 拍講義照片
   ▼
LINE 家庭群組 ──► JR bot（Railway）
                   │ ① AI 讀圖，判斷是課本
                   │ ② 回分類卡片，第一顆是「📚 這是考試範圍」
                   │ ③ 按下去 → Claude 出 50~75 題 → 寫 Ragic（待審核）
                   │ ④ 推審核卡片給 Jason
                   ▼
              Jason 按「上架」
                   │
                   ▼
              bot 回作答連結（帶簽章）
                   │
                   ▼
            考卷網頁（GitHub Pages）
                   │ 只跟 JR 的 /exam/api 說話
                   │ 金鑰從不離開 Railway
                   ▼
              交卷 → 寫分數、更新複習排程 → 推成績卡
                   │
                   ▼
            每天 19:00 推週曆獎章板
```

## 三個設計原則

**網頁永遠拿不到金鑰。** 考卷網頁跑在小朋友的瀏覽器裡，按 F12 就看得到所有前端程式碼。Ragic 家庭金鑰能動整個家庭帳本，一旦外洩就是全家的帳。所以網頁只跟 JR 說話，JR 才跟 Ragic 說話。

**AI 出的題一定要人看過才上架。** Claude 會把課本特有的數字、人名、典故弄錯。審核卡片是唯一需要 Jason 動手的環節，約一分鐘。

**能用 reply 就不要用 push。** 小朋友傳照片、按按鈕都是「先開口」，bot 當場回不計費。只有出題太久超過回覆時限、以及晚上七點的週曆，才動用推播額度。週曆推到群組不論幾人都只算一則，一個月大約三十則，免費方案就夠。

## 跟現有系統的關係

這套跟家庭記帳走同一個架構：拍照進來、AI 解析、提案卡片人工核准、寫進 Ragic、網頁呈現。差別只在把發票換成課本。骨架可以直接沿用。

金鑰一把都不用新增，Ragic 家庭金鑰、Anthropic 金鑰、LINE 通道金鑰全部沿用現有的。
