# 家庭相簿小秘書（family-album）

把照片丟給 LINE 裡的小秘書（或讓它自己去掃爸媽兩人的 Google 雲端硬碟），它會：

1. **自動歸檔**：依拍攝時間分月份、同一張不重複存（LINE 傳過、雲端硬碟又有，只留一張）。
2. **認人**：家人在「認人」頁標一次「這是哥哥 / 妹妹」，之後自動歸類；沒把握的會問「看起來像妹妹，對嗎？」。
3. **AI 寫註記**：每張照片一句話描述＋活動（生日 / 出遊…）＋關鍵字，所以可以用口語找照片。
4. **回顧影片**：每月 1 號自動挑上個月的精選做成影片推到家庭群組；元月再多一支年度回顧。

> 狀態：原型（v0.1）。核心流程已用自動化實測跑過（`npm test`，14 項），
> **但還沒接過真的 LINE / Google / Claude 帳號**，第一次上線請照「上線前要確認」逐項測。

## 架構

```
家庭 LINE 群組 ──▶ LINE webhook ─┐
爸爸的雲端硬碟 ─┐                 ├─▶ 收圖流程：去重 → 縮圖 → 歸月份 → 認臉(本機) → AI 註記(Claude)
媽媽的雲端硬碟 ─┴─▶ 定時掃描 ────┘                    │
                                                      ▼
                    相簿網頁（時間軸 / 人物 / 搜尋 / 認人 / 回顧）  ＋  SQLite + 縮圖（Railway Volume）
                                                      │
                               每月 1 號 ──▶ ffmpeg 做回顧影片 ──▶ push 到家庭群組（1 則）
```

- **Node.js 22 + Express + SQLite（Node 內建）**，單一服務，部署在 Railway（跟 usled-linebot 同一套做法）。
- **認臉在自己的伺服器上算**（face-api，不送雲端）；「誰是誰」完全來自家人自己的標記。
- **Claude 只負責看場景**（在做什麼、值不值得放進回顧）與聽懂口語查詢，不負責認臉。
- **雲端硬碟只讀不寫**：原檔留在各自的雲端硬碟，相簿只存縮圖與索引。

## LINE 怎麼用

| 動作 | 小秘書的反應 | LINE 額度 |
|---|---|---|
| 傳照片 / 影片（一次多張也行） | 全部歸檔，整批只回一則「📥 收到 12 張…」 | reply，免費 |
| `相簿` | 給相簿網頁連結 | 免費 |
| `找 妹妹 生日`、`找 去年夏天 海邊` | 回照片卡片（最多 10 張）＋完整結果連結 | 免費 |
| `那年今日` | 往年同一天的照片 | 免費 |
| `統計`、`統計 2026-10` | 張數、每個人幾張、活動分布 | 免費 |
| `回顧`、`回顧 2026-10`、`回顧 2026` | 已做好的直接回影片；沒做過的先做，做好推 1 則 | 首次 1 則 push |
| `認人` | 給認人頁連結 | 免費 |
| 每月 1 號 20:00 | 自動推上個月回顧到群組 | 每月 1 則 push |

群組裡一般聊天小秘書不會插嘴，只回上面這些開頭的指令。整個月的 push 用量大約 1～3 則，免費的輕用量方案（200 則）就夠。

## 部署（Railway）

1. **新 Service**：連這個 repo，**Root Directory 設 `family-album`**（會用裡面的 Dockerfile，自動裝 ffmpeg 與中文字型）。
2. **加 Volume**：掛在 `/data`。⚠ 沒掛的話每次部署相簿都會清空。
3. **Variables**：照 `.env.example` 填 `BASE_URL`、`ALBUM_TOKEN`、`DATA_DIR=/data`、`LINE_TOKEN`、`LINE_SECRET`、`ANTHROPIC_API_KEY`。
4. **LINE**：建一個新的官方帳號（不要跟公司客服帳號混用）→ 啟用 Messaging API →
   Webhook URL 填 `https://你的網址/line/webhook`、開啟 Webhook、回應模式選「聊天機器人」、開「允許加入群組」。
5. **綁定**：把小秘書拉進家庭群組，在群組輸入 `綁定 你的ALBUM_TOKEN`。綁定後才會收照片（陌生人加好友沒有用）。
6. 傳幾張照片測試 → 輸入 `相簿` 打開網頁 → 到「認人」頁告訴它誰是誰。

### 連結 Google 雲端硬碟（選用）

1. Google Cloud Console 建專案 → 啟用 **Google Drive API** → 建 OAuth 用戶端（類型：網頁應用程式），
   已授權的重新導向 URI 填 `https://你的網址/auth/google/callback`。
2. OAuth 同意畫面的**發布狀態要按「發布」成正式版**（停在「測試中」的話授權 7 天就失效）。
   自用不必送審，授權時會出現「未經驗證的應用程式」警告，按「進階 → 繼續」即可。
3. 把 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 填進 Variables。
4. 相簿網頁 →「設定」→「連結一個 Google 帳號」。爸爸、媽媽各做一次，各自貼上放照片的資料夾網址。
   之後每小時自動掃新照片（子資料夾也會掃）。

## 已知限制（先講清楚）

- **LINE 會壓縮照片、而且會拿掉拍攝時間**。所以用 LINE 傳的照片畫質較低，日期會記成「上傳那天」。
  → 日常隨手拍用 LINE 傳很方便；**舊照片、想留原畫質的，請走雲端硬碟**（會讀到真正的拍攝時間）。
- **Google 相簿 ≠ Google 雲端硬碟**。Google 已不開放程式讀取整個「Google 相簿」，
  照片如果只在 Google 相簿 App 裡，要先下載 / 匯出到雲端硬碟的資料夾才掃得到。
- **小孩的臉比大人難認**（長得快、兄弟姊妹像）。目前設定偏保守：很有把握才自動歸類，其餘會問你。
  同一個孩子請多標幾張不同年紀、不同角度的。若實測不夠準，可以換更強的人臉模型（`src/faces.js` 是獨立模組）。
- 回顧影片目前只放照片（影片檔會歸檔、但不會剪進回顧）。配樂：把 mp3 放進 `/data/music` 就會自動配。
- 相簿網頁靠「通行碼連結」保護，拿到連結的人就看得到。請不要把連結轉傳到家庭以外；要換通行碼就改 `ALBUM_TOKEN`。

## 費用概估

- **LINE**：每月 1～3 則 push → 免費方案。
- **Railway**：一個小服務 + Volume。縮圖每張約 0.2 MB，一萬張照片約 2 GB。
- **Claude AI 註記**：每張照片約 1,500 input + 300 output tokens。
  - 預設 `claude-opus-5-5`：約 US$0.012 / 張 → 一萬張約 US$120。
  - 改 `ALBUM_AI_MODEL=claude-haiku-5-5`：約 US$0.0003 / 張 → 一萬張約 US$3。
  - 建議：**先匯少量照片比較兩個模型寫的註記**，差不多的話大量舊照片用 haiku。
  - 完全不想花：不填 `ANTHROPIC_API_KEY`，歸檔 / 認人 / 回顧都還能用，只是不能用口語找照片。

## 本機開發

```bash
npm install
npm test                                   # 整套實測（假的 LINE / Google / Claude，其餘都是真的）
ALBUM_TOKEN=demo npm start                 # http://localhost:3000/?t=demo
npm run import -- ~/Pictures/家庭 爸爸      # 把一個資料夾整批匯入
npm run recap -- 2026-10                   # 手動做一支回顧
```

需要：Node.js 22.5+、ffmpeg、一套中文字型（Dockerfile 已處理）。
