# 保固條款系統

對外的保固條款網頁 ＋ 機身 QR 標籤產生器。
目的：**在成交當下就把保固界線講清楚並留下公告紀錄**，避免日後為了運費、檢測費之類的衍生費用起爭執。

| 檔案 | 用途 | 對象 |
|---|---|---|
| `index.html` | 保固條款全文、保固年限、狀況判定表、費用表、送修流程、FAQ | **客戶**（掃 QR 或給連結） |
| `label.html` | 產生貼在機身背面的 QR 標籤，可批次帶序號、直接列印 | 內部（出貨前貼標） |
| `terms.md` | 條款純文字版，貼報價單背面、合約附件、LINE 回覆用 | 內部 |
| `USLED保固條款_v2.1.pdf` | A4 完整版，可列印或傳給客戶 | 客戶 |
| `qr.js` | 離線 QR 產生器（不依賴任何外部服務或 CDN） | 程式用 |

**網址**：https://jasonled-sketch.github.io/punch-clock-web/warranty/

## 上線前必做的四件事

### 1. 補上公司聯絡資訊

`index.html` 頁尾的 `<span id="ftContact">` 目前只寫「高雄市岡山區　│　服務電話：請洽您的承辦業務或官方 LINE」。
請改成正式的**公司地址、電話、統一編號**——消費者保護法第 25 條規定保證書應載明製造商名稱與地址，這欄空著會讓整份文件的正式度打折。

公司名稱一律寫 **譽昇科技有限公司**（品牌 USLED）。

### 2. 確認費率

`index.html` 的費用速查表中，運費已寫「一般單程 NT$150 起（依尺寸、重量、地區）」，**檢測費、出勤費、急件費仍寫「依當次報價」**。
這三筆建議直接填數字——**寫明金額的嚇阻力遠大於「依報價」**，客戶事後爭執的空間也小。檢測費尤其重要，那是擋掉「沒壞也送回來檢查」的唯一防線。

### 3. 確認管轄法院

條款第十四條寫的是**臺灣橋頭地方法院**（岡山區的管轄法院）。
若公司登記地不在岡山，請改成正確的地院。

### 4. 印標籤前實掃

打開 `label.html` → 填序號 → 產生 → **列印前先拿手機掃一次**，確認能開啟條款頁再大量印製。

## 日常怎麼用

### 業務成交時

1. 報價單上加一行：「本產品保固依 USLED 保固條款 v2.1，詳見機身 QR Code 或 〈網址〉。」
2. 把連結傳給客戶一次，並在 LINE 對話留下紀錄（這就是「已告知」的證據）。
3. 客戶是自然人消費者時，**一定要給滿 5 天審閱期**，不要當場逼單。

**成交當下一定要講的三句話**（講完客訴會少一半）：

> 「保固一年，US 的主機板五年。**只要是硬體壞掉，零件跟工資我們全免。**」
> 「送修的運費要您自己出，來回都是，這個保固內外都一樣。」
> 「機器如果整台不亮，**先打給我們**，通常是設定問題，講一下就好，不用寄回來花錢。」

### 出貨前

1. `label.html` 批次產生標籤（序號一行一個，**記得填品牌與出廠日**），列印在**合成紙／PET 防水標籤**上。
   出廠日會寫進 QR，客戶掃描後就能看到這台的出廠日與推定保固到期日，單據遺失也查得到。
2. 貼在機身背面靠近電源線出口處，避開會被支架遮住、被水柱直沖的面。
3. 貼上後實掃一次再出貨。

### 客戶報修時

先問三件事，很多狀況電話裡就能解決，不用拆機：

1. 機身序號、出貨日期（判斷在不在保固期內；**掃機身 QR 就能看到出廠日**）
2. **請客戶拍整片畫面的照片或影片**（判斷是整片／行列／區塊的硬體問題，還是設定問題）
3. 最近有沒有洗車、擦撞、換電瓶、自己拆過（判斷是不是第六條的非保固事由）

**如果客戶說「整台都不亮」，這題一定要先擋下來**——十次有八次是關屏指令、自動開關機時段設定被動到，或節目內容是空白的。花三分鐘遠端排除，客戶省下運費和檢測費，你省下一次拆機工時，兩邊都賺。

然後照這個順序講，順序很重要：

> 「這台還在保固內，**只要是硬體壞掉，零件跟維修工資我們全部免費**，不管壞的是模組還是主機板。
> 只有運費要麻煩您自己出，來回都是，保固條款第五條有寫。
> 另外先跟您說一聲，機器寄回來我們會**從拆箱開始全程錄影**，然後跑紅綠藍三色全亮測試，
> **如果三色都正常，那就表示燈珠沒壞**，是字型或設定的問題，那種情況會收一筆檢測費。
> 所以您先拍個照片給我看，能在線上解決就不用寄了。
> 正常排修 3 到 5 個工作天，急著用可以走急件，3 天內出貨，會加一筆急件費。」

**先講免費的，再講要收的。** 客戶翻臉幾乎都是因為先聽到要錢。

### 客戶還是不接受運費時

不要吵「規定就是這樣」，改用買車來比喻，這個每個人都懂：

> 「這就像您買一台新車，車子在保固期內引擎出問題，原廠免費幫您修；
> 但如果您開到台東拋錨，**把車拖回原廠的拖吊費，原廠不會幫您出**。
> 保固保的是產品本身的品質，不是把產品運回來的成本。
> 我們這邊也一樣：**零件跟工資我們扛到底，一毛不收；運送的成本各自負擔。**」

然後把條款連結傳過去，指**第五條**給他看，並把當初傳連結給他的 LINE 對話截圖一併附上。

### 客戶說「我送回去你們還跟我收檢測費？」

> 「機器進來我們要拆箱、上架、接電、一片一片跑三色測試，測完還要復原、重新包裝，
> 這些工不管有沒有找到故障都實際做了。
> 而且我們**從拆箱就開始錄影，一鏡到底錄到結束**，影片留 30 天，您隨時可以叫我們調出來看。
> 但您放心，**只要驗出來是硬體壞掉而且在保固內，檢測費就不收**，直接免費幫您修。
> 這筆費用只會發生在『機器其實是好的』或『問題出在設定』的時候。
> 所以我才會請您先拍照片給我看，能在線上判斷就不用寄，兩邊都省。」

## 條款要點速記

| 項目 | 內容 |
|---|---|
| 公司名稱 | **譽昇科技有限公司**（品牌 USLED）— 不是「譽昇光電」，任何對外文件都不要寫錯 |
| 條款如何生效 | **購買並受領產品即視同同意**，經銷商賣出的也算。有異議請於受領後 7 日內提出 |
| 保固起算 | **出貨日**（整機交付日）。無單據則以機身序號出廠年月＋30 日推定 |
| 保固年限 | US 品牌**控制主機板 5 年**；其餘所有零組件**不分品牌一律 1 年**。DART 等其他品牌全機 1 年 |
| 新品 7 日 | 受領後 7 日內故障，直接聯繫換新，不必送修 |
| 免費 | 判定為**硬體故障**且在保固內 → 零件費全免＋送回公司的維修工資全免 |
| 死燈門檻 | 死燈數**超過總燈珠數千分之三（3‰）**，或雖未超過但已明顯影響辨識 → 算故障。未超過且不影響 → 正常範圍，不在保固 |
| 檢測費 | 三色檢測硬體正常、屬非硬體事項、死燈未達 3‰、或非保固事由不同意維修 → 收檢測費（固定金額）。硬體故障在保固內則**不收** |
| 客戶負擔 | 來回運費（單程 NT$150 起）、到府出勤車馬費與工時、吊車高空車鷹架交管、急件費、包裝材料費、保管費 |
| 檢修錄影 | **自拆箱起全程錄影、一鏡到底**，影片保存 30 天 |
| 異議期 | 對維修結果有異議須於完工後 **30 日內**提出，逾期視同同意 |
| 久未領回 | 逾 30 日 → 保管費 NT$50–450／日；逾 60 日 → 最後催告後依法報廢 |
| 正常工期 | 3–5 個工作天；急件 3 個工作天內，加收急件費 |
| 維修後保固 | **不延長、不暫停**。原本剩 3 個月，修完仍是 3 個月 |
| 責任上限 | 該產品交易價金；不含營業損失等間接損失。**但故意或重大過失（如維修時摔壞）不受此限** |
| 管轄 | 臺灣橋頭地方法院（消費者得選其住所地法院） |

### 硬體 vs 非硬體的判定

這決定要不要收檢測費，是全份條款最常用到的一條：

- **硬體故障**（保固內全免）：整片不亮、行列條波異常、區塊顯示異常、明顯色偏、死燈超過 3‰、主機板不開機、電源無輸出、排線接觸不良
- **非硬體事項**（收檢測費）：字型檔、字寬設定、排版參數、顯示參數、**關屏設定、自動開關機設定、空白節目**、連線與 IP 設定、操作方式

判定方法是 **LED 模組跑紅、綠、藍三色全亮逐片點測**。三色都正常點亮 → 燈珠與驅動 IC 沒壞 → 畫面怪是設定問題。

**「缺一撇」這種說法不要用**，那是主觀認定、容易起爭議。對客戶一律用「整片不亮／行列條波異常／區塊顯示異常／明顯色偏」這四種可驗證的描述。

### 客戶說「有幾顆燈不亮，你們要免費修」

> 「LED 在製程上本來就允許極少數燈珠失效，業界通則是抓**千分之三**。
> 我們會實際數給您看：**超過千分之三，或者雖然沒超過但已經明顯影響辨識，那就算故障，保固內免費修**。
> 沒超過又看不太出來的，那是 LED 的正常範圍，全世界的廠商都一樣。
> 檢測過程我們全程有錄影，數字怎麼來的您可以調影片看。」

**不要跟客戶講「缺一撇」**——那是主觀判斷，講了就是替自己製造爭議。一律用可驗證的四種描述：整片不亮、行列條波異常、區塊顯示異常、明顯色偏。

## 修改條款的做法

條款內容存在兩個地方，**改動時務必兩邊同步**：

- `index.html` 的 `<section id="terms">` 區塊（客戶實際看到的）
- `terms.md`（紙本與 LINE 用）

改完之後：

1. 更新 `index.html` 裡的 `TERMS.version` 與 `TERMS.effective`（在頁面底部的 `<script>` 開頭）。
2. 同步更新 `terms.md` 開頭的版本與生效日。
3. 舊客戶適用**購買當時**的版本（條款第十三條第一項），**不溯及既往**，所以舊版不要刪掉——請另存為 `terms-v<舊版號>.md` 與 `USLED保固條款_v<舊版號>.pdf` 留檔。

## 為什麼沒有線上簽署

因為客戶多半不會簽，而且很多是經銷商賣出的，根本沒機會當面簽。

所以 v2.1 改用**「購買即視同同意」**的架構（條款第一條）：條款公告在機身 QR、網頁與出貨文件上，客戶買了、收了貨就視同同意，有異議請在 7 天內提出。這在 B2B 與經銷通路是通行做法，也避開了「拿不到簽名 = 沒有依據」的死結。

要讓這個架構站得住腳，**出貨時務必做到兩件事**：

1. **機身一定要貼 QR 標籤**（條款的公告管道，缺了這個「已公告」就說不通）
2. **出貨文件上加註一行**：「本產品保固依 USLED 保固條款 v2.1，詳見機身 QR Code 或 〈網址〉。」

日後若還是想要簽名存證（例如大單、客製案），線上簽署的程式碼在 git 歷史裡（v2.0 版本的 `index.html`），可以隨時取回加裝。

## qr.js 技術說明

自行實作的 QR 產生器，**不依賴任何外部服務或 CDN**（列印標籤的電腦離線也能用，且不會把序號送到第三方伺服器）。

```js
const qr = QRLite.make('https://example.com/', 'M');  // 回傳 {version, size, modules, mask, ecLevel}
QRLite.toSVG(qr, {quiet: 2});                          // SVG 字串
QRLite.toCanvas(canvasEl, qr, {scale: 8});             // 畫到 canvas
```

- 支援 Byte mode（UTF-8）、version 1–10、錯誤更正 L／M／Q／H
- 自動選版本、自動選最佳 mask（依 ISO/IEC 18004 的四條懲罰規則）
- 開發時以 `jsqr` 解碼器做過 550 筆隨機字串驗證，version 1–10 × 四種錯誤更正等級全數通過
- 內容超過 version 10 容量會丟出錯誤；標籤網址請保持簡短

修改 `qr.js` 後請重新驗證：產生幾張標籤 → 手機實掃 → 確認能開啟正確網址。
